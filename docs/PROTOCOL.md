# Протокол Полонины, версия 1

Нужен для Android-версии: всё, что ниже, телефон должен делать так же, как компьютер.

## 1. Поиск устройств — UDP, порт 45454
Каждые 2,5 с — JSON (UTF-8) на `255.255.255.255:45454` и на broadcast-адрес каждой сети:
```json
{"app":"polonyna","v":1,"id":"<uuid устройства>","name":"Олена","username":"olena",
 "deviceName":"Ноутбук Олени","deviceType":"laptop","os":"Windows","avatar":"<sha1-16 или ''>",
 "port":45455,"ask":false}
```
- `deviceType`: `computer` | `laptop` | `tablet` | `phone`.
- `ask:true` — «ответьте сразу»: получатель шлёт свой маячок отправителю (unicast).
- Нет маячков 9 с — устройство считается вне сети. «Сигнал» = сколько маячков пришло за 12,5 с (5 = отлично).
- На Android для приёма broadcast нужен `WifiManager.MulticastLock`.

## 2. Передача — TCP, порт 45455 (если занят — любой, он указан в маячке)
Одно соединение = один кадр:
```
[4 байта: длина заголовка, big-endian][заголовок JSON UTF-8][данные файла, payloadLength байт]
```
Заголовок всегда содержит: `v, type, senderId, senderName, senderPort, payloadLength`.
Получатель, обработав кадр, отвечает **одним байтом**: `1` — принято, `0` — отклонено, и закрывает соединение.
Только после байта `1` отправитель считает сообщение доставленным. Заголовок ≤ 256 КБ, файл ≤ 2 ГБ.

## 3. Типы кадров
| type | поля | смысл |
|---|---|---|
| `hello` | — | ручное подключение по IP |
| `message` | `messageId, chatType, chatId?, group?, messageKind, text, mimeType, fileName, fileSize, duration, waveform, timestamp, forwarded, system` | сообщение |
| `receipt` | `status:"read", messageIds[]` | прочитано (только личные чаты) |
| `profile_request` | — | «пришли фото профиля» (если `avatar` в маячке изменился) |
| `profile` | `avatarHash, name, username` + JPEG в данных | фото профиля |
| `call_offer` / `call_answer` | `callId, sdp` | звонок (WebRTC SDP, без STUN, кандидаты только локальные) |
| `call_reject` / `call_busy` / `call_cancel` / `call_end` | `callId, reason?` | завершение звонка |

- `chatType`: `direct` (чат = id отправителя), `group` (`chatId` = id группы, `group = {id, title, members:[{id,name}]}`),
  `lan` (общий канал «Локальний Wi-Fi», рассылается всем, кто сейчас в сети).
- `messageKind`: `TEXT`, `PHOTO`, `AUDIO` (webm/opus, `duration` в секундах, `waveform` — 48 чисел 0–31),
  `VIDEO` (кружок, webm vp8/opus), `FILE`, `SYSTEM` (`system = {event:"group_created", title}`).
- Повтор с тем же `messageId` игнорируется, но подтверждается байтом `1`.

## 4. Дополнения версии 0.2 (совместимы с версией 1)
- В маячке поле `links: [{ip, prefix, type}]` — все подключения устройства, `type`: `cable` | `wifi` | `virtual` | `other`.
  Получатель находит запись с `ip` = адрес отправителя пакета и узнаёт, через что тот подключён.
- Проверка «одна сеть»: адрес устройства должен входить в подсеть одного из своих подключений **и** устройство должно
  ответить на кадр `ping` (TCP, без данных, ответ — байт `1`). Время ответа показывается как «перевірено · N мс».
- Приватные сообщения: в кадре `message` поле `ttl` (секунды: 10, 30, 60, 300, 3600, 86400), только `chatType: direct`.
  Получатель показывает содержимое только по нажатию, затем шлёт кадр `opened` `{messageIds:[...]}`;
  с этого момента у **обоих** через `ttl` секунд сообщение и его файл удаляются. Пересылка запрещена.

## 5. Дополнения версии 0.3
- `delete` `{messageIds:[...], chatType, chatId?}` — «Удалить у всех». В личном чате любой из двоих может удалить любое
  сообщение, в группе и «Локальном Wi-Fi» — только своё. Если получатель не в сети, команда ждёт в очереди (до 7 дней).
  Получатель удаляет сообщение и полученную копию файла.
- Видеозвонки: в `call_offer` / `call_answer` поле `video: true`, SDP содержит видео. Если у кого-то нет камеры,
  он только принимает видео (recvonly). В журнале звонка `call.video = true`.
